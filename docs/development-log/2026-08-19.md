#### 背景与目标

- 用户希望沿用 Codex 的"开发会话 + 审批会话"双 Agent 工作流到 DSH Web（本机 0.1.0-rc.6，3080 端口）：一个会话专注 code 开发，一个会话专注方案审批，通过会话间消息协作提升开发效率。
- 核对 DSH 源码后确认：所有 Web 会话共享同一 DSH 进程；原生 session-reference 服务存在但 Web GUI 未暴露选择器 UI，无跨会话消息总线；可行路径是按 Cordis 插件机制开发自定义 bundle（与既有 maid-atelier 皮肤同模式）。

#### 实现（dsh-deep-whale/session-bridge，独立包，非 code 仓库）

- **插件形态**：namespace 插件（导出 name/inject/apply），ctx.tools.register(defineTool(...)) 注册 4 个模型工具；cordis.patch.yml 一行 insert；经 dsh plugin --profile web add 挂载进 web profile 的 bundles（package.json 的 dsh.profile.bundles）。
- **工具**：mailbox_send（向指定会话或 board 公告板发消息）、mailbox_poll（读本会话新消息+公告板，游标去重每条只读一次）、mailbox_inspect（经 ctx.sessionQuery.listSessions() 列出全部持久化会话 id/cwd/未读数）、mailbox_board（公告板最近 N 条）。
- **存储**：<DSH_HOME>/session-bridge/（append-only JSONL：mailbox/<sid>.jsonl、board.jsonl、cursors/<sid>.json），损坏行容错跳过；Key 不落盘。
- **构建**：tsdown 多入口（index.mjs + store.mjs），单元测试 node --test 5 项。

#### 验证与踩坑

- **单测**：5/5 通过（send/poll 往返、游标去重、board 广播、未读计数、损坏行容错）。
- **端到端**：重启 DSH 后四个工具进入全部会话 agent 工具视图；实测 inspect 列出 12 个会话、send 直接消息与公告板、poll 读取、二次 poll 为空（游标生效）、board 读取，全部 PASS。
- **踩坑**：dsh-tools 的 parameter spec 中 required 字段一旦出现必须为 true（表示加入必填数组），required: false 直接抛 UNSUPPORTED_SCHEMA 导致插件加载失败；可选参数应省略 required。该问题先由 Claude Code 修复构建产物，随后本会话同步回源码并重建验证无回归。
- **重启**：DSH web 重启后插件生效；重启脚本 dsh-deep-whale/restart-dsh.ps1（kill 3080 监听 → 以日志重定向启动新进程）。
